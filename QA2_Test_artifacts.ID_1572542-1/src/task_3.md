# Test Plan — раздел «Корпоративное обучение»

# 1) Вступление
Настоящий документ является тест-планом раздела "Корпоративное обучение".
В нём определены цели и объём тестирования (что входит и что исключено),
критерии приёмки/приостановки, применяемые подходы и техники (функциональное,
кросс-браузерное, smoke, регрессия), необходимые ресурсы и окружение, и риски.
Документ служит основой для согласования ожиданий
между заказчиком, разработкой и QA и используется для планирования, контроля и
отчётности по тестированию.

# 3) НЕ будут протестированы

Авторизация, личные кабинеты, профили пользователей - требуют зарегистрированных аккаунтов; публичная страница "Корпоративное обучение" доступна без авторизации.

Административная панель для управления контентом - требует специальных прав доступа; не относится к публичной части сайта.

Обработка данных после отправки форм - серверная обработка заявок, сохранение в базу данных, отправка email-уведомлений; проверка серверной логики выходит за рамки тестирования интерфейса.

Другие разделы сайта - тестируется только раздел "Корпоративное обучение"; остальные разделы ("О Школе", "Поступающим", страницы кампусов) не входят в текущий объём работ.

Мобильные приложения - план охватывает только веб-версию сайта в браузерах; нативные iOS/Android приложения не тестируются.

Производительность и нагрузочное тестирование - отсутствуют требования к скорости работы сайта; тестирование под высокой нагрузкой не включено.

Безопасность и проверка уязвимостей - проверка защищенности от взлома требует специализированных инструментов; проводится отдельной командой безопасности.

Поисковая оптимизация и аналитика - настройки для поисковых систем (SEO), счетчики посещений (Google Analytics, Яндекс.Метрика) проверяются маркетинговой командой.

Доступность для людей с ограниченными возможностями - проверка работы программ чтения с экрана и соответствия стандартам доступности не приоритезированы в текущем релизе.



# 4) Тестовые единицы

Форма заявки на корпоративное обучение

● Поле "Как вас зовут?" (текстовое):
  - ввод валидного имени (кириллица, латиница);
  - запрет ввода цифр и спецсимволов;
  - проверка минимальной/максимальной длины;
  - пустое значение → сообщение об ошибке.

● Поле "Какую компанию представляете?" (текстовое):
  - ввод названия компании (кириллица, латиница, цифры допустимы);
  - пустое значение → поведение формы.

● Поле "Электронная почта" (email):
  - валидный формат: test@example.com, user.name@company.co.uk;
  - невалидный формат: test, test@, @example.com, test@example → сообщение об ошибке;
  - пустое поле → блокировка отправки.

● Поле "Номер телефона" (tel):
  - валидный формат: +7 (XXX) XXX-XX-XX;
  - автоформатирование при вводе;
  - запрет ввода букв;
  - проверка длины (мин/макс количество цифр);
  - пустое поле → сообщение об ошибке.

● Чекбокс согласия на обработку персональных данных:
  - обязательность установки для активации кнопки "Отправить";
  - кликабельность ссылки "Политика обработки персональных данных" (открытие документа в новой вкладке);
  - попытка отправки без чекбокса → блокировка.

● Кнопка "Отправить":
  - активация при корректном заполнении всех обязательных полей и установленном чекбоксе;
  - неактивна при незаполненных полях;
  - блокировка после клика (защита от повторной отправки);
  - визуальная обратная связь при клике (изменение состояния).

● Результат отправки:
  - успешная отправка → модальное окно с подтверждением;
  - ошибка отправки → сообщение об ошибке;
  - очистка полей после успешной отправки.

Навигационное меню

● Пункты основного меню (О Школе, Поступающим, Корпоративное обучение, Высшее образование, Партнерам):
  - кликабельность каждого пункта;
  - корректность переходов на соответствующие страницы;
  - выделение активного раздела.

● Hover-эффекты:
  - изменение цвета/стиля при наведении курсора на каждый пункт меню;
  - плавность анимации (если есть).

● Логотип Школы 21:
  - отображение в header;
  - клик по логотипу → переход на главную страницу;
  - корректность изображения (без искажений).

● Адаптивность меню:
  - на экранах ≥1024px → полное горизонтальное меню;
  - на экранах <1024px → трансформация в burger-меню;
  - клик по burger-иконке → открытие/закрытие мобильного меню;
  - закрытие меню при клике вне области меню.


Видеоконтент на странице

● Загрузка видео:
  - автоматическая загрузка превью при открытии страницы;
  - отсутствие ошибок загрузки;
  - корректный размер и пропорции видеоблока.

● Воспроизведение:
  - запуск видео при клике на play;
  - качество изображения (отсутствие артефактов, размытия);
  - наличие звука, корректная громкость;
  - отсутствие задержек и прерываний воспроизведения.

● Элементы управления:
  - кнопка play/pause (переключение состояний);
  - перемотка (drag по timeline);
  - регулятор громкости (ползунок, mute/unmute);
  - кнопка fullscreen (переход в полноэкранный режим и выход из него).

● Кросс-браузерность:
  - работоспособность в Chrome, Firefox, Safari, Edge;
  - работоспособность на мобильных устройствах (iOS Safari, Chrome Android).

# 5) Критерии приёмки (Pass/Fail)

PASS, если:

● 0 открытых дефектов уровней Blocker/Critical; не более 2 дефектов Major; любое количество Minor/Trivial допустимо.

● Выполнены ключевые сценарии:
  - Формы заявок отправляются с валидными данными и отображают результат.
  - Валидация email работает корректно (принимает валидные форматы, отклоняет невалидные с сообщением об ошибке).
  - Навигационное меню: все ссылки кликабельны и ведут на корректные страницы.
  - Модальные окна открываются и закрываются корректно.
  - Футер: ссылки на документы работают.
  - Адаптивность: корректное отображение на desktop (≥1366×768) и mobile (<768px).

● Тестирование пройдено минимум в 2 браузерах (Chrome, Firefox, Safari или Edge).

● Есть артефакты: скриншоты, баг-репорты.

FAIL, если:

● Есть ≥1 дефект Blocker/Critical, или нарушены ключевые сценарии, или функциональность нестабильна на разных браузерах.


# 6) Приостановка / Возобновление

Приостановка, если:

- Обнаружен ≥1 дефект Blocker (сайт не открывается, страница недоступна) или ≥3 дефекта Critical (формы не работают, навигация сломана, модальные окна не открываются).

- Нестабильность: краши, зависания, «белые экраны» ≥2 раз за тестовую сессию.

- Непригодное окружение: браузер не работает, сайт заблокирован, нет доступа, неверная версия билда.

- Существенное изменение требований, делающее текущие тест-кейсы неактуальными.

Возобновление, когда:

- Исправлены все Blocker/Critical дефекты, предоставлен новый билд.

- Smoke test пройден успешно (страница открывается, формы работают, навигация функционирует).

- Подтверждена стабильность: полный прогон ключевого сценария без крашей.

- Окружение восстановлено: браузер работает, доступ к сайту есть, версия билда корректна.

- Тестовая документация актуализирована (если требования изменились).

# 7) Задачи тестировщиков

- Разработка тест-кейсов и чек-листов; подготовка тестовых данных.
- Настройка окружения (браузеры, разрешения экрана).
- Smoke тестирование каждого билда.
- Функциональное тестирование по тест-кейсам.
- Кросс-браузерное и адаптивное тестирование.
- Регрессионное тестирование после фиксов.
- Создание скриншотов и артефактов.
- Заведение баг-репортов, ретесты, верификация фиксов.
- Ежедневные/еженедельные отчеты о прогрессе.
- Актуализация документации.
- Финальный Test Summary Report.

# 8) Артефакты тестирования

- Тест-план (текущий документ).
- Реестр тест-кейсов и чек-лист регрессии.
- Отчеты о прогонах (Pass/Fail статистика).
- Скриншоты ключевых шагов и работы в разных браузерах.
- Баг-репорты с описанием, шагами, приоритетом и скриншотами.
- Еженедельные отчеты о прогрессе.
- Финальный Test Summary Report (метрики, дефекты, риски, рекомендации).
